### 🔍 Истинная техническая причина (Задержка индексации REST API):

На Polymarket работают **два абсолютно разных механизма передачи данных**:

1. **Живой WebSocket (`wss://ws-subscriptions-clob.polymarket.com`) — 0 мс задержки:**
   * Работает в реальном времени прямо из биржевого стакана.
   * Когда вы непрерывно смотрите на экран, браузер через WebSocket получает **каждую сделку, каждый сдвиг Bid/Ask и каждый тик каждую секунду**.
   * Поэтому в живом эфире график всегда плотный и динамичный.

2. **История REST Data API (`data-api.polymarket.com/trades`) — задержка индексации 1–2 минуты:**
   * База данных REST API не работает со стаканом напрямую — в неё данные пишутся фоновым асинхронным индексатором (ETL-пайплайн).
   * **Индексатор Data API отстает от живого сокета на 60–120 секунд прямо во время идущего раунда!**

### 🛠️ Как мы это решили в коде (v5.6):

Чтобы график **никогда не терял секундную плотность и не превращался в прямую линию при перезагрузке страницы**:

1. **🛡️ Энергонезависимый кэш живого потока (`sessionStorage`):**
   * В [`js/live_trading.js`](file:///c:/Z/-V-CODE-/-PM-APPS-/TV-CHART--CCXT/-APP-V-222-/js/live_trading.js) все тики высокой частоты, приходящие из WebSocket и локального тикера каждую секунду, непрерывно кэшируются в `sessionStorage`.
   * При нажатии `F5` приложение считывает накопленный живой поток и **бесшовно сшивает его с историей API**.
   * Все микроколебания, которые были получены через сокет за последние 1–2 минуты, **больше не стираются** и не заменяются плоской линией.

2. **⚡ Мгновенное включение WebSocket до гидратации:**
   * Сокет подписывается в первую же миллисекунду, минимизируя разрыв между историей и текущим моментом.
