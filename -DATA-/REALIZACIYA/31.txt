Создание такого приложения требует грамотной работы с потоковыми данными и правильной архитектуры, чтобы избежать задержек, особенно учитывая, что Polymarket перешел на архитектуру ордербука (CLOB — Central Limit Order Book).

Ниже представлен детальный план реализации, учитывающий механику rolling-рынков и требования к производительности.

1. Архитектура и стек технологий

Для обеспечения максимальной скорости и отсутствия тормозов при частом (секундном) обновлении данных необходимо использовать правильные источники и инструменты.

▫️ Фронтенд: Чистый JavaScript/TypeScript или любой легковесный фреймворк (Vue/Svelte/React).
▫️ Графики: `lightweight-charts` от TradingView. Это идеальный выбор, так как библиотека рендерит графики на HTML5 Canvas, что позволяет без тормозов отрисовывать десятки обновлений в секунду.
▫️ Получение исторических данных: Polymarket Gamma API (REST API) для загрузки списка рынков, поиска текущего активного 5-минутного рынка и получения последних исторических свечей/цен.
▫️ Получение потоковых данных: Polymarket CLOB WebSocket API. Никакого поллинга (отправки REST-запросов каждую секунду). Цены должны прилетать через вебсокет, чтобы минимизировать задержку и избежать блокировок по Rate Limit.

—

2. Пошаговый план реализации приложения

▫️ Шаг 1. Поиск активного rolling-рынка. Rolling-рынки на Polymarket технически представляют собой постоянно создающиеся новые рынки (condition_id / token_id). Каждые 5 минут старый токен экспайрится (рассчитывается), и торговля переходит на новый. При старте приложения необходимо сделать REST-запрос к Gamma API (например, `[https://gamma-api.polymarket.com/events](https://gamma-api.polymarket.com/events)`), отфильтровав события по тегам или слагу (slug) рынка (например, `btc-updown-5m`). Из ответа нужно извлечь ID токена (обычно токен "Yes"), у которого статус активности открыт, а время экспирации наступит в ближайшие минуты.
▫️ Шаг 2. Инициализация графика Lightweight Charts. Создается контейнер, в котором инициализируется график. Для соответствия твоим требованиям необходимо жестко зафиксировать шкалу Y: параметр `autoscale: false`, `minValue: 0`, `maxValue: 100`. Линия графика инициализируется через `chart.addLineSeries()`.
▫️ Шаг 3. Подключение к WebSocket. Устанавливается соединение с `wss://[ws-subscriptions-clob.polymarket.com/ws/market](https://ws-subscriptions-clob.polymarket.com/ws/market)`. В вебсокет отправляется сообщение о подписке на канал `market` (или `trades`) с указанием найденного `token_id`.
▫️ Шаг 4. Обработка входящих данных и масштабирование цен. Polymarket торгуется в USDC от $0.00 до $1.00. При получении цены из вебсокета (например, $0.52), ее нужно умножать на 100, чтобы получить формат 0–100 центов, который тебе нужен.
▫️ Шаг 5. Агрегация таймфреймов (ТФ). Для переключения ТФ (1с, 5с, 15с, 30с, 1м) на фронтенде создается буфер. Вебсокет присылает тики асинхронно. Твоя логика должна собирать эти тики. Если выбран ТФ 15с, скрипт каждые 15 секунд берет последнюю актуальную цену из буфера и пушит ее в график методом `series.update({ time: timestamp, value: price })`. Для линейного графика (LineSeries) достаточно просто передавать закрытие периода.
▫️ Шаг 6. Ротация рынков (Rolling механика). Это самый важный шаг. Приложение должно знать время окончания текущего 5-минутного рынка. За 10–15 секунд до экспирации приложение должно фоном запросить ID следующего рынка, подписаться на него по вебсокету и, как только старый рынок остановится, бесшовно продолжить рисовать линию уже по данным нового токена на том же графике.

3. Критические нюансы Polymarket, которые необходимо учесть

За последнее время архитектура Polymarket сильно изменилась, сместившись в сторону профессионального трейдинга.

▫️ Разница между ценой последней сделки (Last Trade) и Mid-Market. На низколиквидных рынках сделки могут происходить редко (реже 1 раза в секунду). Чтобы линия двигалась живо и отражала реальное состояние рынка, лучше подписываться не только на сделки (trades), но и на изменения ордербука (книги ордеров), рассчитывая "Mid-price" — среднее значение между лучшим бидом (покупкой) и лучшим аском (продажей).
▫️ Стартовая цена 50c. Polymarket AMM и маркетмейкеры всегда открывают новые 5-минутные рынки с вероятности 50% ($0.50). При бесшовной склейке графиков в момент перехода (каждые 5 минут) на графике будет происходить резкий сброс цены к уровню 50, что нормально для rolling-рынков, но это нужно понимать при визуализации.
▫️ Формат времени. Lightweight Charts требует передачи времени (timestamp) строго в секундах (Unix Timestamp в секундах), а не в миллисекундах (как это по умолчанию делает `Date.now()` в JS). Если передать миллисекунды, график выдаст ошибку или улетит в далекое будущее.

4. Возможные ошибки и пути их решения

▫️ Ошибка: Утечка памяти и тормоза из-за метода setData.
Решение: Никогда не используй `series.setData()` для добавления новых точек в реальном времени. Этот метод полностью перерисовывает всю историю. Для новых секундных тиков нужно использовать исключительно метод `series.update()`.
▫️ Ошибка: График "рвется", если нет торгов в течение секунды.
Решение: Если выбран ТФ 1 секунда, а сделок или изменения стакана за эту секунду не было, скрипт все равно должен сгенерировать точку для этой секунды, использовав значение цены из предыдущей секунды. Иначе линия графика будет иметь дыры или визуально "прыгать" по оси X.
▫️ Ошибка: Отвал WebSocket соединения.
Решение: Обязательно реализовать пинг-понг механизм и автореконнект. Соединения с CLOB Polymarket могут периодически обрываться. Приложение должно ловить событие `onclose`, делать паузу в 1-2 секунды и переподключаться, попутно запрашивая исторические свечи через REST, чтобы заполнить возможную дыру на графике во время обрыва.
▫️ Ошибка: Блокировка CORS при локальной разработке.
Решение: REST API Polymarket иногда может ругаться на CORS, если запросы идут с `localhost` без правильных заголовков. В среде разработки можно использовать локальный прокси (например, через Vite/Webpack) или настроить заголовки, если запросы идут напрямую. Для вебсокетов проблемы CORS обычно не существует.
▫️ Ошибка: Ограничения API (Rate Limits).
Решение: У Gamma API довольно строгие лимиты для неавторизованных пользователей. Все запросы на поиск рынков нужно кэшировать и минимизировать. Поиск нового рынка для переключения (раз в 5 минут) лимиты не нарушит, но попытки сканировать API каждую секунду приведут к бану IP. Именно поэтому основной поток цен обязан идти только через WebSocket.
